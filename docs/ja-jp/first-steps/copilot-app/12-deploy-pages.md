GitHub Pages に Space Quiz をデプロイして、誰でもアクセスできるようにします。Copilot はワークフローの準備とデプロイの案内を行いますが、変更をレビューし、サイトが公開されたことを確認するのはユーザーの責任です。

このレッスンでは、次の操作を行います。

- Copilot に GitHub Pages のデプロイ設定を依頼します。
- マージする前にワークフローとプル リクエストをレビューします。
- デプロイの進行状況を確認し、公開されたサイトを検証します。

## シナリオ

Space Quiz はすでに GitHub リポジトリにありますが、簡単に試せる方法はまだありません。単一ファイルのサイトを GitHub Pages で公開すれば、サーバーやランタイム依存関係を追加せずに公開 URL から利用できます。

## Copilot にデプロイの準備を依頼する

> [!WARNING]
> プル リクエストを作成すると、コードがコミットおよびプッシュされる場合があります。このプロンプトを送る前に、承認設定と対象リポジトリを確認してください。**Approve all** を選択している場合、別の確認プロンプトが表示されるとは限りません。

`space-quiz` の Copilot app セッションで、次のプロンプトを送信します。

```plaintext
このリポジトリの GitHub Pages デプロイを準備してください。必要に応じて Web サイトをビルドし、変更が既定のブランチに反映された後に GitHub Pages へデプロイする GitHub Actions ワークフローを作成してください。README がまだない場合は、アプリとローカルでの実行方法を説明する README を追加してください。これらの変更を含むプル リクエストを作成し、そのリンクと必要な Pages の設定または権限を報告してください。マージ、自動マージの有効化、Pages 設定の変更、デプロイは行わないでください。停止して、レビューを待ってください。
```

## ワークフローとプル リクエストをレビューする

1. リポジトリに README がない場合に限り、README が追加されていることを確認します。
2. ワークフローのビルドとデプロイの手順、トリガー、権限を含め、プル リクエストの変更をレビューします。
3. マージ前のプル リクエストではなく、既定のブランチからデプロイするワークフローになっていることを確認します。
4. 必要な修正を依頼して、更新された差分をレビューします。マージを承認する前に、必須のプル リクエスト チェックがすべて成功するまで待ちます。

## マージとデプロイを承認する

> [!WARNING]
> 次のプロンプトは、レビュー済みのプル リクエストのマージ、リポジトリの Pages 設定の変更、サイトの公開をエージェントに許可します。レビューを完了し、リポジトリとプル リクエストを確認してから送信してください。承認設定によっては、別の確認プロンプトなしでこれらの操作が実行されます。

`<PR_NUMBER>` をレビューしたプル リクエストの番号に置き換え、別のプロンプトとして送信します。

```plaintext
このリポジトリのプル リクエスト <PR_NUMBER> をレビューし、マージとデプロイを承認しました。GitHub Actions を使って GitHub Pages を有効にし、必須チェックが成功した後に限り、そのプル リクエストだけをマージしてください。デプロイが成功するまで監視し、公開された Web サイトの最終 URL を報告してください。Pages の有効化やマージに必要な権限がない場合は、私が承認または実行する必要がある操作を正確に説明してください。サイトが公開されるまでは成功と報告しないでください。
```

## デプロイを確認する

1. GitHub Actions のデプロイ実行が成功するまで確認します。
2. 報告された URL を開き、Space Quiz が表示されることを確認します。

エージェントが Pages の有効化やプル リクエストのマージを行えない場合は、提示された具体的な手順に従ってください。デプロイが成功し、公開サイトが読み込まれるまで完了と見なさないでください。
